开启子代理必须配合同步并行工作,不能干等子代理返回。

**Why:** 子代理效率不一定比主代理高,干等就失去开启子代理的意义。用户明确批评:"如果你是长时间的等待子代理,就没有意义了,因为子代理还不一定有你干的好。" 开启子代理的目的是提高工作效率,只在主代理同步做另一部分工作时才成立。

**How to apply:**
- 启动子代理做独立扫描/检查时,主代理同时做另一部分工作(读代码、写实现、验证假设)
- 责任分工:主代理做高风险入口改动(§5 文件,子代理禁区),子代理做独立只读分析(调用图、契约清单、风险点、并行维度审视)
- 典型场景:bug 审视时多开子代理并行 grep 不同维度,主代理同步读关键文件;3G 实现时主代理改 PlayerPersistenceService/game.js,子代理并行扫 Phase 4 散落点或独立维度的风险
- 反例:启动子代理输出清单后,主代理干等清单返回,期间不做任何工作 — 这是浪费,等同串行
- 子代理输出后,主代理应已有充分理解,直接动手实现,不再二次阅读子代理已读的代码
