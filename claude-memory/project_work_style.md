## 搜索用朴素中文短词

搜索任务必须先从最朴素的中文短查询词开始尝试(如"cline 最新套餐"),再逐步缩小范围。不要一开始就给子代塞一大段英文长 prompt 做泛调研。

- 第一轮:用 2-5 个字的中文短词直接搜(网页/论坛)
- 被反爬挡住(如 DuckDuckGo 返回 202、V2EX/知乎 403)不是终点,要主动绕路:
  - 直接 WebFetch 抓目标页原文(博客/官方文档/GitHub)
  - 换搜索引擎(Bing、站内搜索 site:v2ex.com、Google)
  - 让用户给链接,但先尽力自己找,别轻易要
- 拿到原文后,直接针对用户的具体问题找答案,不要泛泛总结

搜索引擎对自然语言长 prompt 的支持远不如短关键词。

## 抓住用户给的主问题线索,直接验不要甩给子代

当用户在对话中已经给出具体线索或反问(如"是不是必须 npm i -g cline 才能拿优惠"),必须把这条当作主问题直接去验证,不要甩给子代做泛泛调研,也不要绕弯。

1. 识别用户反问句里的核心变量(npm i -g cline、优惠码、首月价)
2. 直接 WebFetch/Grep 已知相关原文,在原文里找这个变量,而不是再发一轮搜索
3. 子代调研只用于"我不知道去哪找"的情况;一旦有候选源,自己抓原文验证
4. 永远不要把"用户已经指出的方向"再外包出去

## 承诺要立刻落盘

对用户说"记住了/下次注意"之后,必须在同一轮内立刻 Write 到 memory 文件并更新 MEMORY.md 索引。否则下一轮对话完全不会保留,承诺等于零。

1. 任何"下次我会注意"类的承诺,立刻 Write 一条 memory 文件
2. 同时更新 MEMORY.md 索引加一行指向该文件
3. 不要等用户提醒,不要拖到下一轮
4. 落盘后才能在回复里说"记下了"

口头承诺毫无信用,用户已多次发火。

## 用户说"我在X环境里"就立刻对齐到X

用户说"我在 X 环境里"/"我已经在 Y 里了"时,必须立刻把所有后续方案对齐到 X/Y,不能再走会套娃或绕路的原方案。

1. 用户每说一句环境信息(proot / root / termux / 已在某目录),立刻在脑内把当前工作目录和运行环境切到那个,不要还按上一轮的假设走
2. 如果用户已在 proot 里,所有命令直接给 proot 内能跑的,不要再套 `proot-distro login`、不要让用户跑为 termux 设计的脚本
3. 改脚本/加抽象前先问:用户要的是这个吗?还是只要一行命令?默认走最短路径,别自作主张扩方案
4. 用户说"不要乱搞"时立刻停手回滚,别再追加"改进"

## 批准计划后持续推进

已获批准的多步实现计划,除非用户叫停/遇阻/高风险,否则不要每步停下,持续推进下一个低风险切片。

- 选中下一个低风险切片、测试、单独提交,不要在每个 commit/test 后停下问"继续吗"
- 仍要停的情况:遇到 blocker、破坏性/共享状态操作超出已批准范围、需求不清、需要确认的风险
- 用户明确说过"继续啊,不要停下来呀,我没让你停,你就不要停"
