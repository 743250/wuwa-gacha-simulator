## 分阶段任务

### P0 · 识图后复刻抽卡分析（纯抽卡入口核心页）

- 用识图通道逐块标注参考图：字号、颜色、卡片、头像、进度条、日期、UP/歪标记、底部栏。
- 扩展 `src/gacha/analysis.js`：按池聚合（限定 / 专武 / 常驻 / 联动）、总消耗星声、生涯评分称号、出金时间线行数据。不要改抽卡概率。
- 新建分析页组件（不要在现有 StatsTab 上硬改到面目全非）；现有统计可保留作开发对照。
- 补分析计算测试 + 组件契约测试。
- 验收：对照参考图并排检查，不允许“差不多”。

### P1 · 同仓库纯抽卡入口

建议形态：

- `index.gacha.html` + `src/gacha-app/main.js`
- `npm run dev:gacha` / `npm run build:gacha`
- 后续 Capacitor/WebView 只打这个产物

入口只挂：时间线、唤取、角色仓库、角色详情、海市、商店、分析、存档导入导出。

明确不挂：冒险 tab、编队、日常、副本、深塔、海墟、战斗 overlay、电台若依赖战斗产出则先藏。

`initApp()` 拆成 `initGachaApp()`，不调用 `initBattleResources` / `initDungeonMerge` / `initBattleUiBridge`。

### P2 · 3.5 / 3.6 静态角色补全（战斗仍不做）

- 补 bannerNames：秧秧·玄翎、穗穗、清宵、景燃。
- 核实并显式填写 3.5 四星陪跑。
- 从 encore 拉清宵 / 景燃 / 秧秧·玄翎 / 穗穗的 portrait、lore、官方技能/链原文。
- 清宵、景燃技能/共鸣链页显示「已收录，专属战斗数据待补」，禁止编造倍率或 effect。
- 漂泊者·导电是否加入，等用户确认（官方已有，当前模拟器没有）。

### P3 · 角色信息与商店体验

- 角色仓库 / 详情在纯抽卡入口可用：属性、武器、共鸣链文案、故事语音。
- 商店：月相、月卡、礼包；去掉依赖体力/战斗的补给文案。
- 背包只留抽卡相关货币与材料，去掉「去副本掉声骸」死链。

### P4 · APK 打包

- Capacitor 或现有 WebView 壳，只打包 `build:gacha`。
- 存档用 localStorage + 导出/导入 JSON；Android 再评估文件系统。
- 竖屏优先，分析页按参考图做长页滚动。

## 明确不做
