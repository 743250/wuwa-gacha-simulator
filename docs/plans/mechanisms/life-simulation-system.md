# 现实生活、经济与资产节点系统 · 设计草案

> 立项日期：2026-07-10  
> 状态：讨论草案，已确认自由存款、定时结婚节点与非终止式结局模型  
> 定位：把现有“抽卡 → 养成 → 战斗”扩展为“生活 → 收入 → 自由消费 → 抽卡/养成 → 自然结果”的长期模拟  
> 重要边界：文中的人民币仅是**主角在游戏世界中的虚拟货币**，不接入真实支付

---

## 一、设计结论

玩家不是身无分文开局，而是带着一笔足以改变人生方向的存款进入游戏。标准示例为初始存款 ¥200,000。

存款首先代表**选择不同人生的自由**。玩家可以用它维持生活、准备结婚，也可以辞掉工作、把大量存款充入游戏，集中享受抽卡和养成。房租、吃饭、通勤、婚恋承诺和家庭责任会持续占用现金；抽卡消费则与这些现实目标竞争同一份预算。玩家每次购买月相，都应当看见银行卡余额真实下降，并承担之后的生活影响。

本系统的核心乐趣不是惩罚玩家花钱，而是让玩家回答：

> 我想把有限的钱和时间，投入到哪一种人生？

首个大额资产节点采用“结婚”：节点在预定时间自然到来，只验证当时存款是否达到 ¥500,000。系统不生成彩礼任务，也不要求玩家提前选择生活方式。

本设计不设置唯一正确的人生，也不预先划分玩家类型。结婚、角色收藏、工作与娱乐的平衡，都只是玩家行为可能形成的结果，不是系统发放的任务身份。

## 二、体验目标

### 1. 每一抽都能感受到代价

- 抽卡所用月相由主角的人民币购买。
- 购买后立即从游戏内银行卡扣款。
- 界面同时显示余额、下次发薪日和近期必须支付的账单。
- 免费获得的星声、活动奖励和波纹仍按现有规则运行，不折算成人民币。
- 游戏不评价玩家“该不该抽”，只诚实呈现这次选择改变了什么。

### 2. 存款不是分数，而是选择空间

高存款允许玩家：

- 承受临时失业、生病或家庭事件。
- 在喜欢的卡池出现时集中投入。
- 支付结婚、买房或创业等大额节点。
- 改善住房、交通和饮食，节省未来时间或恢复更多状态。
- 在一段时间内完全不上班，把生活重心放在游戏上。
- 放弃结婚等长期承诺，换回现金、时间和生活自主权。

低存款不会结束游戏，但会缩小选择空间。玩家可以重新工作、兼职、降低消费、出售物品；如果重要节点到来时资产不足，则接受该段人生内容的坏结局。

### 3. 大额资产节点自然形成长期压力

系统可以存在结婚、买房等大额节点，但它们不是自动接取的任务。节点必须满足三个条件：

1. 条件简单透明，例如“当前存款达到 ¥500,000”。
2. 不替玩家预留资金，不生成专用进度，也不限制玩家提前花掉资产。
3. 节点到来时一次性结算结果；无论好坏，主模拟都继续运行。

玩家是否把这个数字当成目标，完全由玩家自己决定。

### 4. 日常不变成重复劳动

第一次上班、做饭、通勤应完整呈现；重复内容允许通过日程模板快速结算。真正需要玩家操作的是例外事件、资源冲突和重要决定。

## 三、核心玩法闭环

```text
规划当天日程
  ↓
上班 / 加班 / 兼职 / 采购 / 做饭 / 休息 / 探索地图 / 战斗
  ↓
消耗时间、精力、饱腹与现金
  ↓
获得工资、生活改善或鸣潮资源
  ↓
支付账单或自由使用存款
  ↓
决定储蓄、改善生活还是购买月相
  ↓
抽卡与养成 → 挑战内容 → 获得星声
  ↓
进入下一天，等待工资、卡池与生活事件
```

现有抽卡、养成和战斗是“线上娱乐世界”；新增生活系统是主角所在的“现实世界”。两个世界共享时间，但货币严格分层。

## 四、自由行为与自然结果

系统不提供“选择人生”的按钮，也不在后台把玩家归入固定类别。它只提供统一规则：一天有有限时间，账户有真实余额，工作能够赚钱，生活需要开支，充值会扣除存款，卡池会按日期结束。

玩家每一天都可以重新决定：

- 今天是否上班、请假、旷工或辞职。
- 是否加班、兼职、学习或寻找其他赚钱方法。
- 是否做饭、外食、休息、约会或进入游戏。
- 是否购买月相，以及购买多少。
- 是否保留足够存款应对未来的结婚节点，或者把钱花在别处。

这些选择不形成互斥分支，也不会锁住后续内容。玩家可以连续半年努力工作，某个版本辞职投入游戏，存款下降后重新求职；也可以原本打算攒到 ¥500,000，后来把钱投入喜欢的卡池。系统不要求玩家登记或取消任何计划。

### 可能自然出现的生活状态

以下只是用于检验系统自由度的例子，不是游戏预设分类：

- 玩家暂时不工作，用存款维持生活并大量购买月相，因此拥有充足游戏时间和丰富收藏，同时逐渐消耗生活储备。
- 玩家保持正常工作，把游戏作为消遣，在工资、日常生活和少量充值之间持续调整预算。
- 玩家积极寻找收入机会，把大量时间用于工作和成长，很少进入游戏，最终让存款达到结婚节点的要求。
- 玩家原本想攒钱结婚，后来改变想法，将时间转向职业、游戏或暂时没有明确目标的生活。
- 玩家完成结婚后减少工作，在新版本集中游玩；也可能因为关系与生活成本变化而重新调整消费。

这些状态可以随时互相转化，系统不显示“你已进入某种人生”。

### 结果反馈原则

- 不设置“完美人生”总分榜。
- 不按工作、结婚或充值行为给玩家贴人格标签。
- 月报只记录现金、时间、关系和游戏进度发生了什么变化。
- 事件由当前条件触发，不因玩家被归类为某种生活方式而触发。
- 内容解锁只依赖具体事实，例如“连续 30 天未上班”或“当前存款达到 ¥500,000”，而不是依赖隐藏分类值。
- 真正的设计失败不是玩家没结婚或没抽到角色，而是系统迫使所有人采用同一种最优生活方式。

## 五、货币与账户

### 1. 货币分层

| 账户 | 用途 | 是否可相互兑换 |
|---|---|---|
| 银行存款（¥） | 工资、房租、吃饭、交通、资产节点、购买月相 | 可购买月相，不可反向提现 |
| 随身现金（¥） | 小额线下消费，可作为后续沉浸功能 | 可与银行存款互转 |
| 月相 | 充值货币 | 按模拟器商城档位由人民币购买 |
| 星声 | 抽卡通用资源 | 月相可按现有规则转换为星声 |
| 唤声涡纹等 | 直接抽卡 | 维持现有获取和消耗规则 |

首版可以只实装“银行存款”，暂不区分随身现金。

### 2. 现金流原则

- 所有人民币变化必须写入流水。
- 流水至少记录日期、时间、分类、金额、地点和余额。
- 未来支出必须进入账单日历，让玩家能够提前规划。
- 游戏内充值不得悄悄自动发生；每次人民币转月相都需要玩家确认。
- 确认窗口必须显示充值后余额和 30 天内的必要支出。

确认示例：

```text
购买月相 ×6480                         -¥648

购买前余额                            ¥6,214
购买后余额                            ¥5,566
距下次发薪                            9 天
30 天内必要支出                       ¥3,280
结婚筹备缺口                         ¥41,000
```

### 3. 开局资产

开局不采用统一“穷人模板”，由开局档案决定：

| 档案 | 初始存款 | 收入与压力 | 定位 |
|---|---:|---|---|
| 稳健生活 | 较高 | 工作稳定、可支配收入中等 | 新玩家推荐 |
| 普通青年 | 中等 | 收支平衡，需要规划长期目标 | 标准体验 |
| 追梦开局 | 较低 | 收入成长快，但前期抗风险弱 | 高压力体验 |

玩家也可以自定义存款。自定义档案不参与未来可能加入的挑战成就，避免通过极高存款跳过全部经济玩法。

## 六、资产节点系统

### 1. 节点不是任务

资产节点是会随时间或事件自然到来的世界节点。系统不会把它放进任务栏，不追踪“完成百分比”，也不会要求玩家事先声明目标。玩家只是提前知道世界中可能发生这件事，然后继续自由生活。

例如，结婚节点的唯一条件是：

```text
当前银行存款 ≥ ¥500,000
```

玩家开局拥有 ¥200,000。这笔钱没有被标记为彩礼，也不受保护，可以全部用于生活、充值或其他消费。

### 2. 结婚节点行为

结婚节点到来时：

1. 读取当前银行存款。
2. 存款达到 ¥500,000：扣除 ¥500,000，记录结婚成功，开放婚礼与婚后生活内容。
3. 存款不足 ¥500,000：记录结婚失败的坏结局，关闭依赖本次结婚成功的内容。
4. 结算完成后，时间继续推进，玩家照常工作、生活、探索和抽卡。

示例：

```text
结婚需要                         ¥500,000
当前银行存款                     ¥200,000
还差                             ¥300,000

结婚节点：资产不足

你没有在这个时间点准备好 ¥500,000，婚事没有完成。
这段故事已经结束，但你的生活仍会继续。
```

该节点有明确的结算时间，但没有阶段奖励、关系信任检查或彩礼专用账户。玩家不能在坏结局后补交 ¥500,000 改写已经发生的结果；如未来设计新的感情内容，应通过新的独立节点发生，而不是回滚历史。

### 3. 钱始终是可自由支配的

- 不为结婚自动冻结任何金额。
- 不显示强制的结婚进度条。
- 不因玩家充值而提示“挪用了彩礼”。
- 不根据玩家曾经拥有多少钱判断资格，只检查节点到来那一刻的当前余额。
- 玩家可以今天拥有 ¥500,000，明天全部充值；只要节点尚未到来，系统不干涉。
- 玩家也可以持续工作，在节点到来前将余额从 ¥200,000 提升到 ¥500,000。

### 4. 通用资产节点

同一规则可以用于其他现实选择：

| 节点 | 条件示例 | 成功结果 | 条件不足的结果 |
|---|---:|---|---|
| 结婚 | 当前存款 ≥ ¥500,000 | 扣除费用，开放婚后内容 | 记录婚事失败，婚后内容不开放 |
| 买房机会 | 当前存款 ≥ 房屋价格 | 扣除房款，获得住宅资产 | 错过本次房源，继续租房生活 |
| 买车机会 | 当前存款 ≥ 车辆价格 | 扣除车款，改变通勤方式 | 错过优惠，维持原交通方式 |
| 旅行邀约 | 当前存款 ≥ 旅行费用 | 扣除费用，进入旅行内容 | 错过本次旅行，日常继续 |
| 创业窗口 | 当前存款 ≥ 启动资金 | 扣除资金，开启经营内容 | 机会结束，保留原有工作与生活 |

节点只验证自身明确需要的数据，不共享隐藏的“人生进度”。坏结局只关闭与该结果有因果关系的内容，不给玩家添加全局减益。

### 5. 示例经济起点（待平衡）

| 项目 | 标准档案示例 |
|---|---:|
| 初始银行存款 | ¥200,000 |
| 结婚节点费用 | ¥500,000 |
| 初始资金缺口 | ¥300,000 |
| 税后月薪 | 待确定 |
| 基础月生活成本 | 待确定 |

收入与生活成本只决定玩家积累或消耗存款的速度，不生成“结婚任务”。

## 七、时间系统

### 1. 统一世界时间

所有模块使用同一个游戏时间源：

- 工作排班和发薪日。
- 三餐、睡眠和通勤。
- 房租和账单日期。
- 卡池开放与结束。
- 日常、周常、版本和体力恢复。
- 商店营业时间和地图事件。

禁止各模块自行偷偷推进日期。任何行动都应通过统一时间服务结算。

### 2. 时间粒度

首版采用“30 分钟为最小行动单位”，不要求玩家现实等待：

| 行动 | 时间示例 |
|---|---:|
| 通勤 | 30～90 分钟 |
| 正常上班 | 8 小时 |
| 加班 | 1～3 小时 |
| 买菜 | 30～60 分钟 |
| 做饭和吃饭 | 60 分钟 |
| 外卖和吃饭 | 30 分钟 |
| 副本战斗 | 20～30 分钟，向上按一个时间单位结算 |
| 整理养成 | 30 分钟 |
| 睡眠 | 玩家选择时长 |

抽卡动画本身不应大量吞噬游戏时间；单次抽卡操作统一结算少量时间即可，避免玩家因观看动画受罚。

### 3. 错过与截止

- 迟到影响工资、绩效或关系，但偶发迟到不直接丢工作。
- 未支付账单先进入宽限期，再产生滞纳或服务受限。
- 卡池结束后不可回退时间补抽。
- 资产节点按各自时间到来，并使用到达瞬间的世界状态结算一次。
- 时间不可随意倒退，读档除外。

## 八、地图与地点

首版使用节点式城市地图，后续可更换成大型可视化地图而不改变底层规则。

```text
出租屋 ── 便利店 ── 地铁站 ── 公司
   │                     │
菜市场 ── 公园 ── 商业街 ── 餐馆
                         │
                    银行 / 商城
```

| 地点 | 主要功能 | 核心取舍 |
|---|---|---|
| 出租屋 | 睡觉、做饭、查看存档与账单、养成角色 | 省钱但消耗家务时间 |
| 公司 | 上班、加班、请假、升职事件 | 获得收入但消耗精力 |
| 菜市场 | 购买食材 | 价格低，需要做饭 |
| 便利店 | 快速购买食物和日用品 | 时间灵活，价格较高 |
| 餐馆 | 吃饭、约会、关系事件 | 恢复高，消费高 |
| 公园 | 免费休息、散步、约会 | 消耗时间，恢复心情 |
| 商业街 | 购物、充值活动、随机消费事件 | 容易产生额外支出 |
| 银行 | 查看流水、余额与定期储蓄 | 管理自由存款 |

大地图的价值在于“到哪里、花多久、做什么”，不是单纯增加移动距离。

## 九、工作系统

### 1. 基础结构

工作提供稳定现金流，同时占用一天中最完整的时间块。工作是维持和扩大选择空间的方式，不是每天强制完成的签到任务；玩家可以辞职、旷工或暂时脱产。

核心状态：

- 基础工资。
- 工作日与上下班时间。
- 绩效。
- 疲劳。
- 请假余额。
- 晋升进度。
- 发薪日。

### 2. 玩家决策

- 准时上班：稳定获得工资与绩效。
- 加班：增加当期收入或晋升机会，但损失精力和自由时间。
- 请假：换取时间，可能损失收入或请假额度。
- 兼职：收入效率低于主业，但时间更灵活。
- 学习：短期没有收入，长期提高工资上限。
- 跳槽：承担一段收入不稳定期，换取新的发展机会。
- 辞职：立即释放大量时间，停止稳定收入，开始消耗存款生活。

### 3. 快速结算

完成首次教学后，普通工作日允许选择“一键按计划完成”。系统自动结算通勤、上班和预设用餐，仅在发生重要事件时暂停。

## 十、吃饭、精力与生活状态

首版只保留五个核心资源：

| 状态 | 作用 |
|---|---|
| 银行存款 | 支付现实生活和月相购买 |
| 时间 | 决定一天能完成多少行动 |
| 饱腹 | 影响精力恢复和健康事件概率 |
| 精力 | 影响工作、兼职和战斗安排 |
| 心情 | 影响关系、工作事件与冲动消费事件 |
首版暂不加入卫生、口渴、体重等细碎数值，避免沦为状态条维护游戏。

吃饭的核心取舍：

- 做饭：便宜、恢复稳定，但占用采购和烹饪时间。
- 外卖：节省时间，价格中高，连续使用降低生活质量。
- 餐馆：价格高，可触发约会和关系事件。
- 便利食品：应急选择，便宜快速，但恢复较差。
- 不吃：短期省钱省时，之后通过精力和健康风险偿还代价。

## 十一、抽卡与现实经济的连接

### 1. 购买链路

```text
银行存款（¥）
  ↓ 玩家确认购买
月相
  ↓ 按现有兑换规则
星声
  ↓
唤取
```

不得让抽卡核心直接扣人民币。人民币消费属于商城/生活经济领域；抽卡领域只认识月相、星声和波纹，以保持边界清晰。

### 2. 消费反馈

抽卡统计新增现实维度：

- 本月鸣潮消费。
- 累计鸣潮消费。
- 本次角色的实际人民币成本。
- 免费资源贡献比例。
- 本月消费占收入比例。
- 充值后的当前银行余额。

这些信息用于回顾，不使用羞辱性文案，不把消费高低与玩家道德绑定。

### 3. 冲动与冷静机制

- 首次大额消费只增加明确确认，不强制现实时间冷却。
- 玩家可以主动设置月度鸣潮预算。
- 达到预算时给出提醒，但允许继续消费。
- 可以开启“生活保护”：当充值会侵占 30 天内必要账单时，需要二次确认。
- 结婚所需的 ¥500,000 不受保护；玩家可以自由花掉。

---

## 十二、失败、后果与补救

### 1. 不设置轻易死档

经济困难应产生新的玩法，而不是让玩家无法继续：

- 临时兼职。
- 出售非必要物品。
- 与房东协商宽限。
- 向家人或伴侣求助，同时产生关系影响。
- 降低住房或生活标准。
- 寻找更高工资工作。

### 2. 后果分级

| 级别 | 情况 | 后果 |
|---|---|---|
| 提醒 | 余额即将不足 | 预算提示，无直接处罚 |
| 紧张 | 延迟一项支出 | 心情、服务状态或少量费用影响 |
| 困难 | 连续拖欠、长期过劳 | 工作、健康或关系事件恶化 |

结婚节点条件不足会被记录为该段内容的坏结局，但不属于整个模拟器的失败。它关闭婚礼、婚后生活等相关内容，玩家随后继续正常生活。

### 3. 非终止式结局

本模拟器中的“结局”是某段可能性的结束，不是整个存档结束：

- 结婚失败后仍可上班、辞职、吃饭、探索地图、充值和抽卡。
- 已拥有的角色、资产和游戏进度全部保留。
- 不弹回标题画面，不强制读档，不要求重新开局。
- 坏结局可以永久关闭有直接因果关系的内容，例如本次婚礼和对应婚后事件。
- 坏结局不能附带无关惩罚，例如降低抽卡概率、清空存款或禁止工作。

“部分内容永远无法体验”本身就是选择与时间真实生效的证明。若玩家希望看另一种结果，可以在另一个存档中采用不同生活方式，而当前存档继续承载已经发生的人生。

### 4. 防止最优解单一化

- 不能让“每天加班 + 永不抽卡”成为唯一正确答案。
- 过度加班应降低状态并错过关系事件。
- 完全不娱乐会持续降低心情和生活满意度。
- 合理抽卡和娱乐可以恢复心情，但不能直接产生人民币收益。
- 系统不得因为玩家把存款用于游戏，就额外施加与实际现金流无关的隐藏惩罚。

## 十三、事件系统

事件由时间、地点、状态和历史选择共同触发。

### 1. 生活事件

- 房东通知续租或涨租。
- 公司发放奖金。
- 地铁延误导致迟到风险。
- 冰箱损坏，需要维修或更换。
- 生病，需要休息或就医。

### 2. 资产与选择事件

- 玩家提前得知结婚节点将在未来到来以及 ¥500,000 条件。
- 存款首次达到 ¥500,000，但系统不自动要求冻结或保留资金。
- 结婚节点到来，根据当时余额记录成功或坏结局。
- 玩家买房、买车、旅行或创业时面对其他明确的资产门槛。

### 3. 抽卡事件

- 喜欢的角色与重要账单同期出现。
- 版本更新发放免费资源。
- 玩家在低落状态下收到充值活动提示。
- 提前出金后，可以选择停止或继续追共鸣链。

事件不应预设唯一道德答案。选择的价值取决于玩家当前目标和愿意承担的结果。

## 十四、月度结算

每个自然月生成生活报告，让长期变化可见：

```text
7 月生活报告

工资与其他收入                    ¥8,120
基础生活支出                      ¥3,486
鸣潮消费                          ¥1,296
月底余额                        ¥203,338

正常上班                           21 天
加班                               18 小时
自己做饭                           12 次
外卖                               15 次
平均睡眠                          6.6 小时
抽卡                               83 次

本月纪要：你拿到了想要的角色，也因为连续加班错过了两次休息。
```

报告只描述因果，不给玩家打“好人/坏人”分数。

长期报告继续陈述事实，不总结玩家属于哪种生活方式：

```text
过去 90 天，你把大部分时间投入了游戏。

你获得了：完整参与 2 个版本、5 名限定角色、一次深塔满星。
你改变了：离开原工作、生活储备减少 ¥31,420。
接下来仍可选择：继续当前生活 / 寻找兼职 / 重新求职。
```

## 十五、首版可玩范围

第一阶段以“能完整生活 30 天”为目标，不直接制作真正的开放世界。

### 必须实装

- 银行存款与人民币流水。
- 一份固定工作、发薪日和基础请假/加班。
- 辞职、不上班与重新求职。
- 房租、饮食、交通三类生活支出。
- 时间段行动与统一时间推进。
- 出租屋、公司、菜市场、便利店、餐馆五个地点。
- 饱腹、精力、心情三个生活状态。
- 人民币购买月相，并显示购买后的生活影响。
- 定时结婚节点：到达时仅检查当前存款是否达到 ¥500,000，记录成功或坏结局。
- 结局后继续游玩，以及按结果开放或关闭相关内容。
- 30 天生活报告。

### 暂不实装

- 自由行走的 3D/2D 开放地图。
- 复杂恋爱养成和大量可攻略角色。
- 真实贷款利率、税务和投资市场。
- 真实定位、真实银行或真实支付。
- 联机经济和玩家间交易。
- 生育、养老等更远期人生阶段。

## 十六、后续阶段

### Phase A：一个月生活原型

验证时间、工资、吃饭、充值和抽卡是否形成有趣取舍。

### Phase B：长期自由经济

加入工作成长、季度事件和定时结婚节点，验证不同消费与时间安排能否自然产生不可回滚但不终止游戏的结果。

### Phase C：城市地图扩展

增加更多住宅、公司、医院、娱乐场所和交通路线，让地点选择改变生活效率。

### Phase D：更多资产节点

加入买房、买车、旅行和创业等可选节点。所有节点独立检查条件，不组成任务线。

## 十七、实现边界建议

本节只规定未来代码职责，不在本设计阶段直接修改代码。

```text
src/life/
  economy/       银行账户、流水、账单、预算
  schedule/      日程与行动耗时
  work/          工作、工资、绩效、请假
  needs/         饱腹、精力、心情
  milestones/    结婚、买房等定时节点与结果状态
  events/        条件事件与选择
  map/           地点、路线和营业时间
```

关键边界：

- 时间模块是唯一允许推进世界时间的入口。
- 生活经济模块管理人民币；抽卡模块不得直接读写人民币。
- 商城负责人民币到月相的显式交易。
- 资产节点在时间事件中通过经济接口检查余额、扣款并记录结果，不直接操作 UI。
- UI 只展示状态并提交行动，不承担结算逻辑。
- 所有随机事件支持注入随机源，以便稳定测试。

## 十八、验收标准

首版完成时，应当能够回答以下问题：

1. 玩家能否只依靠游戏内生活循环持续游玩至少 30 天？
2. 工资、生活成本和抽卡消费是否都能在流水中完整追溯？
3. 玩家购买月相后，银行卡是否真实扣款且不会重复扣款？
4. 不抽卡、适度抽卡和高额抽卡是否都会自然改变余额与可用时间，而不触发预设分类？
5. 结婚节点是否在预定时刻只检查当前存款是否达到 ¥500,000？
6. 条件不足时，是否记录坏结局、关闭相关内容，然后允许玩家继续完整的日常与游戏循环？
7. 普通工作日能否快速结算，避免重复点击造成疲劳？
8. 现有卡池、日常、版本、体力与新生活时间是否由同一日期驱动？
9. 完全不上班的玩家能否明确看到存款还能支撑多少天，并继续使用全部通用内容？
10. 平衡工作与游戏的玩家是否需要真正取舍卡池，而不是轻易全收集？
11. 专注赚钱的玩家是否有加班之外的成长方式，并能把存款提升到 ¥500,000？
12. 无论结婚结果好坏，是否都不会结束存档、清空进度或施加无关惩罚？

---

## 十九、待用户继续确认

1. 整体基调更偏写实都市压力，还是温暖日常中的轻度规划？
2. ¥500,000 是结婚节点的固定费用，还是以后允许开局调整？
3. 结婚成功后首批开放哪些婚礼或婚后生活内容？
4. 除结婚外，首版是否还需要买房或买车节点？
5. 游戏时间是一日一日快速推进，还是允许玩家细致安排到每半小时？
